# 架构与数据约定

## 为什么保持静态应用

当前需求是个人饮品手帐，日历计算、品牌模板、筛选和备份都可以在浏览器完成。原生 ES Modules 让应用在 Node 本地预览、静态托管或 GitHub Pages 子路径下使用同一份文件，无需构建工具。Playwright 是开发测试依赖，运行页面不加载它。

```text
index.html + style.css + enhancements.css
                 ↓
              app.js                 DOM / 对话框 / 事件与当前视图
          ↙      ↓       ↘
    brands.js  journal.js  storage.js
    品牌配置   纯数据规则   localStorage 读写与恢复
```

## 记录结构

存储键继续使用 `cupnote.journal.v1`。现有 v1 数据不需要迁移。

```json
{
  "version": 1,
  "hasStarted": true,
  "records": [{
    "id": "a-unique-record-id",
    "brand": "luckin",
    "name": "生椰拿铁",
    "date": "2026-10-29",
    "price": 9.9,
    "size": "大杯",
    "temperature": "少冰",
    "sugar": "五分糖",
    "note": "午后的一杯"
  }]
}
```

日期是本地日历键，不是 UTC 时间戳；计算以本地正午为锚点，避免时区转换挪动日期。金额在导入和保存时归一到分，统计先累加整数分再显示。两杯相同饮品使用不同 `id`；备份合并只按 `id` 去重。

## 保存与恢复

1. 首次访问只在内存中生成示例，示例不会导出为个人备份。
2. 保存第一条真实记录后，持久化 `hasStarted` 并退出示例模式。
3. 导入先验证整个文件，再一次性写入；文件中任何一条无效都会阻止本次导入。
4. 若原始本地内容无法解析，普通保存受到保护，原数据保持不动。用户可以导出原始文本，再通过有效备份明确恢复。
5. 若存储配额不足，应用显示临时记录并提醒导出；不会显示保存成功提示。

JSON 是恢复格式，CSV 是查看和分析格式，CSV 不支持导入。CSV 包含 UTF-8 BOM、标准引号转义和公式文本保护。

## 同步边界

`storage` 事件用于同步同浏览器、同来源下其他标签页已完成的写入。当前实现没有跨设备同步、事务锁或并发编辑合并；两个标签页严格同时写入时，仍可能以后一次写入为准。网站来源、浏览器配置文件和设备之间的数据相互独立。

## 验证

`npm test` 覆盖日历边界、金额统计、备份兼容性、CSV 安全、损坏存储与预览服务。`npm run test:e2e` 在桌面和手机尺寸下验证用户实际完成的操作。CI 还在两个时区运行核心测试，避免日期规则只在本机有效。
